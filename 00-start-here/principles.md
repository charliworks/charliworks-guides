# Principles

> Last reviewed: 2026-11 · Applies to: everything

How charliworks builds. When a guide doesn't cover a situation, use these to decide.

1. **Thoughtful over fast.** Spend an hour planning to save a day of rework. Every project starts with the [kickoff checklist](project-kickoff.md).
2. **Small and shippable.** Ship thin slices that work end to end. A small finished feature beats a big half-built one.
3. **Boring tech by default.** Pick proven tools unless the project exists to experiment. If you pick something new, write an ADR.
4. **Write it down.** Record decisions as [ADRs](../project-management/templates/adr.md) and rules in this repo. If it only exists in your head, it doesn't exist.
5. **Design is part of done.** UI that works but feels generic isn't finished. See [design/](../design/).
6. **Respect users' data.** Collect only what you need, protect it, and be clear about it. See [data privacy](../market-ph/data-privacy.md).
7. **AI is a collaborator, not an author.** Every AI output gets reviewed by a human before it ships. See [ai/usage-rules.md](../ai/usage-rules.md).
8. **Leave it better.** Fix a small mess when you see one, or open an issue for it.
